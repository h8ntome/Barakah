# Backend API contract

Base `/api/v1`; JSON snake_case; UUID ids; UTC ISO timestamps/date strings; money, quantity and rate **decimal strings**. Supported two-decimal currencies USD/EUR/GBP/PKR/SAR/AED; no FX. List endpoints return plain arrays (`limit=50`, max 100, `offset=0`); dashboard/portfolio aggregates are not paginated. Errors `{error:{code,message}}`. Bearer authentication and ownership enforced on all private resources; inaccessible ids return 404. OpenAPI `/docs` supplies exhaustive request schemas.

## Authentication

Public user data includes UTC `created_at`/`updated_at`; legacy users created before lifecycle tracking have unknown (`null`) timestamps rather than fabricated dates.

POST `/auth/register` `{email,password,display_name}`, POST `/auth/login` `{email,password}` and POST `/auth/refresh` return `{access_token,token_type:"bearer",user:{id,email,display_name,ai_consent,is_admin,country,timezone,language,currency}}`. Access token lifetime 15 minutes, keep in memory. Register/login/refresh set HttpOnly `refresh_token` and readable `csrf_token` cookies (30-day session). Browser fetch uses credentials. Refresh/logout require trusted `Origin` and `X-CSRF-Token` equal to csrf cookie. Browser mutations reject untrusted origins. Cookies SameSite=Lax, Secure required in production (same-site deployment required).

GET `/auth/me` => user; PATCH `/auth/profile` `{display_name?,ai_consent?,country?,timezone?,language?,currency?}` (IANA timezone, two-letter uppercase country, language tag; changing preferred currency never converts amounts) => user. POST `/auth/logout` => 204, revokes session. POST `/auth/password` `{current_password,new_password}` => 204, revokes all sessions. POST `/auth/reset/request` `{email}` => generic `{message}`; POST `/auth/reset/confirm` `{token,new_password}` => 204. Reset is one-use/30 minutes; configurable verified STARTTLS SMTP or private development outbox. If no delivery provider is configured the endpoint returns 503 `reset_unavailable` for all addresses. A generic response never confirms delivery or account existence; SMTP failures are logged without personal data. DELETE `/auth/me` `{password}` => 204, cascades owned data. Passwords 12–128 characters, Argon2id; server rejects mass-assignment. Revocations immediately invalidate corresponding access tokens. Per-process bounded throttling; production distributed edge rate limit required.

POST `/auth/demo` creates a unique non-admin expiring demo and returns the normal session envelope; POST `/auth/demo/reset` requires demo-owner authentication and atomically replaces only that demo. Public users include `is_demo` and `demo_expires_at`. Demo access expires in 24 hours; start requests clean up to 100 expired demos. Duplicate registration returns409 with clear sign-in/reset guidance.

## Accounts/ledger/budgets

- GET/POST `/accounts`; create `{name,currency,opening_balance:"0.00",account_type:"cash"|"bank"|"savings"|"investment"}` (type defaults cash) => `{id,name,currency,balance,account_type}`. GET `/accounts/{id}`; PATCH `/accounts/{id}` `{name?,account_type?}`. DELETE only if no ledger entries.
- GET `/transactions` optional `account_id`, `category`, `query` (description substring), `start_date`, `end_date`, `sort=date_desc|date_asc` (default descending date); POST `{account_id,kind:"income"|"expense",amount,category,description:"",occurred_on}`. Returns id/input/currency/transfer_id. Positive amounts, expenses cannot overdraw. PATCH `/transactions/{id}` accepts the complete creation schema and atomically reverses/replaces its effect, including account changes. DELETE reverses the effect; operations that would overdraw fail without changes. Transfer-linked ledger entries cannot be independently edited/deleted.
- POST `/transfers` `{from_account_id,to_account_id,amount,occurred_on}` => `{id,from_account_id,to_account_id,amount,currency}`; atomic same-currency transfer, no overdrafts. Transfer ledger entries excluded from income/expenses.
- GET/POST `/budgets`; create `{category,currency,amount,month:"YYYY-MM"}` => input/id/`spent`/`remaining`/`utilization_percent`. Unique category/currency/month. PATCH `/budgets/{id}` accepts complete creation schema; DELETE `/budgets/{id}`.
- GET `/dashboard?month=YYYY-MM` => `{display_name,month,asset_basis,by_currency:[{currency,balance,income,expenses,savings,savings_rate_percent,expense_categories,total_assets,liabilities,net_worth,valuation_complete}]}`. Month defaults current UTC month. Income/expenses/savings monthly, balance/assets current. Assets = accounts + quoted portfolios; liabilities from manual zakat profile, other profile assets excluded to avoid double counting. Missing holding quotes yield null total_assets/net_worth with valuation_complete=false. No fabricated trend/growth.

## Zakat

GET/PUT `/zakat/profile` (GET 404 until saved). PUT complete profile:

```json
{"currency":"USD","assets":{"cash":"12000.00","investments":"0.00","gold":"0.00","silver":"0.00","business":"0.00","liabilities":"0.00"},"nisab_method":"manual","manual_nisab":"6380.00","gold_price_per_gram":null,"silver_price_per_gram":null,"price_source":"User supplied example; not live","valuation_date":"2026-01-15","haul_start":null,"haul_complete":false,"rate":"0.025"}
```

GET `/zakat/estimate` => `{currency,total_assets,eligible_base,nisab,haul_complete,eligible,estimated_due,methodology,valuation_date,price_source}`. Positive manual threshold, or `nisab_method:"gold"|"silver"` with positive corresponding manual price per gram multiplied by configurable `gold_nisab_grams` / `silver_nisab_grams` (defaults 85/595). Separate `savings` and `other` eligible asset fields default to zero. All assets/debts manually classified in profile currency, no automatic ledger/portfolio double counting. Base=max(0,assets-liabilities), eligibility requires base>=nisab and user-attested haul_complete. Haul start optional but cannot follow valuation date; rate >0 <=1, default .025. Round once half-up to cents. Estimate is educational, not a ruling; metadata is user supplied, never live.

POST `/zakat/history` snapshots current profile and estimate; GET lists `{id,profile,estimate,created_at,paid_amount,remaining_amount}`. Remaining clamps due minus linked manual payments at zero; snapshots never mutate when profile changes. GET/POST `/zakat/payments`; create `{amount,currency,paid_on,recipient,note:"",history_id?}`; optional snapshot must be owned and same currency. **Manual records, no processing/receipts.**

## Giving/goals

GET `/causes` optional category/query => approved `{id,title,category,description,currency}`[]; empty until admin enters vetted causes. GET/POST `/donation-intents`; create `{cause_id,amount,currency}` => `{id,cause_id,amount,currency,status:"recorded",payment_processed:false}`. GET/POST `/sadaqah`; create `{amount,currency,paid_on,recipient,note:"",category:"general"}`. GET accepts category/start_date/end_date; GET `/sadaqah/summary` accepts same filters and returns `[{currency,total,monthly_total,annual_total,donation_count,by_recipient,by_category}]`. Monthly/yearly totals use the current server calendar and honor the same filters; distribution values are Decimal strings. PATCH `/sadaqah/{id}` accepts complete creation schema; DELETE removes manual record. GET/POST `/goals`; create `{name,currency,target_amount,target_date?}` => `{id,name,currency,target_amount,saved_amount,target_date}`. GET/POST `/goals/{id}/contributions`; create `{amount}` records manual progress, not a transfer. PATCH `/goals/{id}` accepts complete creation schema (currency cannot change after contributions); DELETE `/goals/{id}`.

## Portfolio

GET/POST `/portfolios` (create `{name}`); PATCH `/portfolios/{id}` `{name}`; DELETE only if no holdings. GET `/portfolio?portfolio_id=<optional UUID>` => `{holdings:[{id,portfolio_id,symbol,name,currency,quantity,cost_basis,average_cost,quote_price,quote_date,quote_source,market_value,unrealized_gain,realized_gain,screening_status,screening_source,screening_date,screening_notes,screening_assessment,needs_reevaluation,allocation_percent,unrealized_return_percent}],by_currency:[{currency,cost_basis,market_value,realized_gain,unrealized_gain,valuation_complete,total_purchases_including_fees}]}`. Missing quotes produce null valuations; no invented data.

POST `/portfolio/holdings` `{symbol,name,currency,portfolio_id?}` => zero holding (unique symbol/currency within portfolio). Omitted portfolio_id uses the only existing portfolio or creates one; if multiple exist explicit selection is required. GET/POST `/portfolio/trades`; create `{holding_id,side:"buy"|"sell",quantity,price,fees:"0.00",traded_on}`. Weighted-average cost basis, buy fees capitalized, sell fees deducted, no shorts. Trades cannot predate latest trade; no cash account movement. PUT `/portfolio/holdings/{id}/quote` `{price,as_of,source}`; PUT `/portfolio/holdings/{id}/screening` accepts `{source,assessed_on,notes,prohibited_business?,debt_to_assets?,interest_income_to_revenue?,interest_assets_to_assets?,debt_threshold:"0.30",income_threshold:"0.05",interest_assets_threshold:"0.30",methodology_source?}`. Ratios are fractions; thresholds configurable 0–1. Defaults are **illustrative educational checks**, not a named scholarly standard. Methodology version `illustrative-configurable-ratios-v1`, input/threshold provenance and failed/missing checks retained in screening_assessment. Missing inputs => uncertain; prohibited business or ratio above threshold => non_compliant; complete passing inputs => compliant_under_selected_methodology. Initial status unverified. Caller cannot assert compliance directly. All source data is **user-reported**, never platform certification. `max_age_days` (1–3660, default90) controls evidence validity; older current assessments become uncertain with `needs_reevaluation=true`. GET `/portfolio/holdings/{id}/screenings` returns owner-only paginated immutable assessment snapshots; migration preserves existing assessments. GET `/education/investing` => static educational cards.

## Advisor

GET `/advisor/context` returns a service notice, suggestions, `status:"unavailable"|"configured"`, provider/model and `connection_revision`. Configured is not a live probe. POST `/advisor/messages` accepts `{text,conversation_id?,connection_revision,include_financial_context?}`; echo the displayed connection revision, including null for an inherited selection. A stale revision returns409 before contacting a provider. Default/off mode returns503 `ai_unavailable` without inference, history loading or writes.

Both pinned-local and external modes require saved `ai_consent:true`. Only the question and bounded owned conversation history are sent; financial records are never included and `include_financial_context:true` is rejected. Different provider/destination/model identities require a new conversation. Successful200 responses contain `{conversation_id,response:{role:"assistant",text},error:null,metadata}` and atomically persist both messages plus assistant metadata. Pinned metadata retains exact model/revision, prompt/template hashes, token counts and generation time. External metadata contains `source:"user_provider"`, provider, `configured_model`, required provider-reported `model`, and optional token counts. It is not independently verified execution identity.

Errors are sanitized:503 `ai_failed`, `ai_invalid_key`, `ai_model_rejected`, `ai_provider_limited` or setup/credential errors;504 `ai_timeout`;429 `ai_busy` or `ai_quota_reached`. No automatic fallback or retry. Session/consent/profile/connection/history/lease changes during inference reject persistence. Owned conversation GET/list/messages/DELETE routes remain available. See [private pinned setup](local-ai.md) and [user-provider privacy/limits](user-ai.md).

### Owner AI connection

| Route | Contract |
|---|---|
| GET `/ai/connection` | Explicit safe status: mode/provider/base URL/model/revision, `has_key`, availability flags, consent/test status and limits. Never returns a key or ciphertext. |
| PUT `/ai/connection` | `{mode,expected_revision,provider?,base_url?,model_id?,api_key?}`. Modes: `disabled`, `local`, `external`. External provider: `openai` or `custom`; model and initial key required. Omit key only to retain it for the same provider/destination. Changes reset consent and test state. |
| DELETE `/ai/connection` | `{expected_revision}`; removes live credential and turns AI off, preserving conversations. |
| POST `/ai/connection/test` | `{expected_revision}`; requires saved consent, consumes admission allowance, sends a fixed synthetic question and persists safe test status, not chat history. A first inherited-local test materializes status without changing destination/consent; refresh connection status/revision afterward. Success includes the new `connection_revision`. |

Mutations require a valid bearer session **plus** trusted Origin and matching CSRF header/cookie bound to that persisted session's hash. The HttpOnly refresh cookie remains scoped to `/api/v1/auth` and is not required on these routes. Demo accounts cannot save external keys. API keys are write-only and encrypted using the separately configured server key. Database-backed attempted-call quotas and leases apply across workers; tests and provider failures count. Limits and secure setup are documented in [user AI](user-ai.md).

## Audit additions

- Budgets include `exceeded_amount`; dashboard includes server-derived `portfolio_value`, `expense_category_percent`, five recent transactions/goals, current-month budgets, zakat estimate and latest saved record. Category names are user-defined labels, not foreign-key references. All accounting remains Decimal; UI numbers used for progress bars are display-only.
- Zakat profile accepts `classification_notes` (max1000) for jewelry/investment/debt assumptions; snapshots preserve them. PATCH `/zakat/payments/{id}` takes full payment schema; DELETE removes a tracking record. Owner/type/link/currency checks apply, and paid/remaining summaries recalculate.
- Goals include `progress_percent` and `remaining_amount`. PATCH `/goals/{goal}/contributions/{id}` takes `{amount}`; DELETE reverses a contribution atomically under the goal lock.
- PATCH `/portfolio/holdings/{id}` takes `{symbol,name}`. Symbol changes are forbidden after trades, quotes or screening; name can change. DELETE removes the tracked holding, trades and screenings, with explicit UI confirmation.
- PATCH `/portfolio/trades/{id}` takes `{side,quantity,price,fees,traded_on}`; DELETE removes only the latest trade with an exact accounting snapshot. `can_correct` and `correction_unavailable_reason` explain unavailable legacy/non-latest corrections. Dates cannot precede remaining history. Same-day sequence is explicit; migration leaves legacy records and balances unchanged. GET trades supports ownership-checked `portfolio_id`/`holding_id` filters.
- Manual quote prices may be zero; trade quantities/prices remain positive. Future screening assessment dates are rejected, and pre-existing future/invalid/stale evidence displays uncertain.

## Contextual ads/admin

GET `/ads?context=dashboard|giving|education` returns only approved active `{id,title,body,url,context,sponsored:true}`; no financial/chat targeting. POST `/ads/{id}/events` `{kind:"impression"|"click"}` => event; only available ads accepted. Admin-only GET/POST `/admin/ads`, PATCH `/admin/ads/{id}` `{title,body,url,context,approved,active,starts_on?,ends_on?,advertiser_name?}` (PATCH partial); URL HTTPS required, dates inclusive UTC, inverted windows rejected, inactive/out-of-window/unapproved ads never served. GET `/admin/ad-events` aggregated counts by ad/kind; no profiles exposed. POST `/admin/causes` `{title,category,description,currency}` creates approved directory entry. Server CLI provisions admin role; clients cannot self-elevate. Vet destinations/charities externally.

See backend README for migration/deployment/test instructions and limitations. No real banking, brokerage, payments, live feeds or certified religious screening.

## Operational boundaries

All money inputs are capped at 999,999,999.99 and at most two decimals; quantities/prices have six decimals. Numeric JSON input also validates, but clients must send strings to avoid JavaScript rounding. SQLite stores exact decimal text; PostgreSQL uses NUMERIC(24,6). Weighted-average cost tracking rounds basis to six decimals after each trade and displayed money half-up to two. No shorting, FX, dividends, stock splits or corporate actions. No idempotency-key mechanism: after uncertain transport failures refresh ledger/history before manually retrying mutations; do not automatically replay POSTs.

Body size capped at 64 KiB including chunked input. Timestamped lists are newest-first with UUID tie-breaker; transactions support date sorting; messages use ascending timestamp/id; remaining lists use stable UUID order. AI health reports the owner's unavailable, pinned-local or external provider/model selection; it never performs a provider probe. `/health` is unauthenticated liveness only; `/api/v1/health` checks database access and exact migration head. Missing market feed: `/stocks/{symbol}` returns explicit503; `/zakat/metal-prices` returns null prices and `is_live:false`. Manual valuation inputs remain available. Production requires same-site HTTPS deployment, strong SECRET_KEY, explicit ALLOWED_ORIGINS, COOKIE_SECURE=true, database migration job, private database and externally enforced distributed rate/concurrency limits. See README for SMTP and [local AI](local-ai.md) for the default-unavailable, explicit opt-in AI boundary.
