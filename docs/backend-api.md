# Backend API contract

Base `/api/v1`; JSON snake_case; UUID ids; UTC ISO timestamps/date strings; money, quantity and rate **decimal strings**. Supported two-decimal currencies USD/EUR/GBP/PKR/SAR/AED; no FX. List endpoints return plain arrays (`limit=50`, max 100, `offset=0`); dashboard/portfolio aggregates are not paginated. Errors `{error:{code,message}}`. Bearer authentication and ownership enforced on all private resources; inaccessible ids return 404. OpenAPI `/docs` supplies exhaustive request schemas.

## Authentication

POST `/auth/register` `{email,password,display_name}`, POST `/auth/login` `{email,password}` and POST `/auth/refresh` return `{access_token,token_type:"bearer",user:{id,email,display_name,ai_consent,is_admin,country,timezone,language,currency}}`. Access token lifetime 15 minutes, keep in memory. Register/login/refresh set HttpOnly `refresh_token` and readable `csrf_token` cookies (30-day session). Browser fetch uses credentials. Refresh/logout require trusted `Origin` and `X-CSRF-Token` equal to csrf cookie. Browser mutations reject untrusted origins. Cookies SameSite=Lax, Secure required in production (same-site deployment required).

GET `/auth/me` => user; PATCH `/auth/profile` `{display_name?,ai_consent?,country?,timezone?,language?,currency?}` (IANA timezone, two-letter uppercase country, language tag; changing preferred currency never converts amounts) => user. POST `/auth/logout` => 204, revokes session. POST `/auth/password` `{current_password,new_password}` => 204, revokes all sessions. POST `/auth/reset/request` `{email}` => generic `{message}`; POST `/auth/reset/confirm` `{token,new_password}` => 204. Reset is one-use/30 minutes; configurable verified STARTTLS SMTP or private development outbox. If no delivery provider is configured the endpoint returns 503 `reset_unavailable` for all addresses. A generic response never confirms delivery or account existence; SMTP failures are logged without personal data. DELETE `/auth/me` `{password}` => 204, cascades owned data. Passwords 12–128 characters, Argon2id; server rejects mass-assignment. Revocations immediately invalidate corresponding access tokens. Per-process bounded throttling; production distributed edge rate limit required.

## Accounts/ledger/budgets

- GET/POST `/accounts`; create `{name,currency,opening_balance:"0.00",account_type:"cash"|"bank"|"savings"|"investment"}` (type defaults cash) => `{id,name,currency,balance,account_type}`. GET `/accounts/{id}`; PATCH `/accounts/{id}` `{name?,account_type?}`. DELETE only if no ledger entries.
- GET `/transactions` optional `account_id`, `category`, `query` (description substring), `start_date`, `end_date`; POST `{account_id,kind:"income"|"expense",amount,category,description:"",occurred_on}`. Returns id/input/currency/transfer_id. Positive amounts, expenses cannot overdraw. PATCH `/transactions/{id}` accepts the complete creation schema and atomically reverses/replaces its effect, including account changes. DELETE reverses the effect; operations that would overdraw fail without changes. Transfer-linked ledger entries cannot be independently edited/deleted.
- POST `/transfers` `{from_account_id,to_account_id,amount,occurred_on}` => `{id,from_account_id,to_account_id,amount,currency}`; atomic same-currency transfer, no overdrafts. Transfer ledger entries excluded from income/expenses.
- GET/POST `/budgets`; create `{category,currency,amount,month:"YYYY-MM"}` => input/id/`spent`/`remaining`/`utilization_percent`. Unique category/currency/month. PATCH `/budgets/{id}` accepts complete creation schema; DELETE `/budgets/{id}`.
- GET `/dashboard?month=YYYY-MM` => `{display_name,month,asset_basis,by_currency:[{currency,balance,income,expenses,savings,total_assets,liabilities,net_worth,valuation_complete}]}`. Month defaults current UTC month. Income/expenses/savings monthly, balance/assets current. Assets = accounts + quoted portfolios; liabilities from manual zakat profile, other profile assets excluded to avoid double counting. Missing holding quotes yield null total_assets/net_worth with valuation_complete=false. No fabricated trend/growth.

## Zakat

GET/PUT `/zakat/profile` (GET 404 until saved). PUT complete profile:

```json
{"currency":"USD","assets":{"cash":"12000.00","investments":"0.00","gold":"0.00","silver":"0.00","business":"0.00","liabilities":"0.00"},"nisab_method":"manual","manual_nisab":"6380.00","gold_price_per_gram":null,"silver_price_per_gram":null,"price_source":"User supplied example; not live","valuation_date":"2026-01-15","haul_start":null,"haul_complete":false,"rate":"0.025"}
```

GET `/zakat/estimate` => `{currency,total_assets,eligible_base,nisab,haul_complete,eligible,estimated_due,methodology,valuation_date,price_source}`. Positive manual threshold, or `nisab_method:"gold"|"silver"` with positive corresponding manual price per gram (85g gold / 595g silver). All assets/debts manually classified in profile currency, no automatic ledger/portfolio double counting. Base=max(0,assets-liabilities), eligibility requires base>=nisab and user-attested haul_complete. Haul start optional but cannot follow valuation date; rate >0 <=1, default .025. Round once half-up to cents. Estimate is educational, not a ruling; metadata is user supplied, never live.

POST `/zakat/history` snapshots current profile and estimate; GET lists `{id,profile,estimate,created_at,paid_amount,remaining_amount}`. Remaining clamps due minus linked manual payments at zero; snapshots never mutate when profile changes. GET/POST `/zakat/payments`; create `{amount,currency,paid_on,recipient,note:"",history_id?}`; optional snapshot must be owned and same currency. **Manual records, no processing/receipts.**

## Giving/goals

GET `/causes` optional category/query => approved `{id,title,category,description,currency}`[]; empty until admin enters vetted causes. GET/POST `/donation-intents`; create `{cause_id,amount,currency}` => `{id,cause_id,amount,currency,status:"recorded",payment_processed:false}`. GET/POST `/sadaqah`; create `{amount,currency,paid_on,recipient,note:"",category:"general"}`. GET accepts category/start_date/end_date; GET `/sadaqah/summary` accepts same filters and returns `[{currency,total}]`. PATCH `/sadaqah/{id}` accepts complete creation schema; DELETE removes manual record. GET/POST `/goals`; create `{name,currency,target_amount,target_date?}` => `{id,name,currency,target_amount,saved_amount,target_date}`. GET/POST `/goals/{id}/contributions`; create `{amount}` records manual progress, not a transfer. PATCH `/goals/{id}` accepts complete creation schema (currency cannot change after contributions); DELETE `/goals/{id}`.

## Portfolio

GET/POST `/portfolios` (create `{name}`); PATCH `/portfolios/{id}` `{name}`; DELETE only if no holdings. GET `/portfolio?portfolio_id=<optional UUID>` => `{holdings:[{id,portfolio_id,symbol,name,currency,quantity,cost_basis,average_cost,quote_price,quote_date,quote_source,market_value,unrealized_gain,realized_gain,screening_status,screening_source,screening_date,screening_notes,screening_assessment}],by_currency:[{currency,cost_basis,market_value,realized_gain,unrealized_gain,valuation_complete}]}`. Missing quotes produce null valuations; no invented data.

POST `/portfolio/holdings` `{symbol,name,currency,portfolio_id?}` => zero holding (unique symbol/currency within portfolio). Omitted portfolio_id uses the only existing portfolio or creates one; if multiple exist explicit selection is required. GET/POST `/portfolio/trades`; create `{holding_id,side:"buy"|"sell",quantity,price,fees:"0.00",traded_on}`. Weighted-average cost basis, buy fees capitalized, sell fees deducted, no shorts. Trades cannot predate latest trade; no cash account movement. PUT `/portfolio/holdings/{id}/quote` `{price,as_of,source}`; PUT `/portfolio/holdings/{id}/screening` accepts `{source,assessed_on,notes,prohibited_business?,debt_to_assets?,interest_income_to_revenue?,interest_assets_to_assets?,debt_threshold:"0.30",income_threshold:"0.05",interest_assets_threshold:"0.30",methodology_source?}`. Ratios are fractions; thresholds configurable 0–1. Defaults are **illustrative educational checks**, not a named scholarly standard. Methodology version `illustrative-configurable-ratios-v1`, input/threshold provenance and failed/missing checks retained in screening_assessment. Missing inputs => uncertain; prohibited business or ratio above threshold => non_compliant; complete passing inputs => compliant_under_selected_methodology. Initial status unverified. Caller cannot assert compliance directly. All source data is **user-reported**, never platform certification. GET `/education/investing` => static educational cards.

## Advisor

GET `/advisor/context` => `{welcome_message:{role:"assistant",text,is_demo},starter_questions:[...]}`. POST `/advisor/messages` `{text,conversation_id?}` => `{id,conversation_id,role,text,created_at,is_demo}`. Input 1–1000 chars. Requires explicit `ai_consent:true` even in mock. Default deterministic mock. Configured local loopback HTTP adapter sends **only current text** `{text}` and accepts `{text}` response, no financial records/history automatically transmitted, no weights bundled. GET `/advisor/conversations` => `{id,created_at}`[]; GET `/advisor/conversations/{id}/messages`; DELETE `/advisor/conversations/{id}` erases history. Consent revocation blocks future prompts; history explicitly erasable. Educational output, no religious or investment authority.

## Contextual ads/admin

GET `/ads?context=dashboard|giving|education` returns only approved active `{id,title,body,url,context,sponsored:true}`; no financial/chat targeting. POST `/ads/{id}/events` `{kind:"impression"|"click"}` => event; only available ads accepted. Admin-only GET/POST `/admin/ads`, PATCH `/admin/ads/{id}` `{title,body,url,context,approved,active,starts_on?,ends_on?}` (PATCH partial); URL HTTPS required, dates inclusive UTC, inverted windows rejected, inactive/out-of-window/unapproved ads never served. GET `/admin/ad-events` aggregated counts by ad/kind; no profiles exposed. POST `/admin/causes` `{title,category,description,currency}` creates approved directory entry. Server CLI provisions admin role; clients cannot self-elevate. Vet destinations/charities externally.

See backend README for migration/deployment/test instructions and limitations. No real banking, brokerage, payments, live feeds or certified religious screening.

## Operational boundaries

All money inputs are capped at 999,999,999.99 and at most two decimals; quantities/prices have six decimals. Numeric JSON input also validates, but clients must send strings to avoid JavaScript rounding. SQLite stores exact decimal text; PostgreSQL uses NUMERIC(24,6). Weighted-average cost tracking rounds basis to six decimals after each trade and displayed money half-up to two. No shorting, FX, dividends, stock splits or corporate actions. No idempotency-key mechanism: after uncertain transport failures refresh ledger/history before manually retrying mutations; do not automatically replay POSTs.

Body size capped at 64 KiB including chunked input. List order is stable UUID order except messages (timestamp/id). Advisor local response limit 32 KiB/8,000 chars, timeout 10 seconds; local provider GET /health is checked by `/ai/health`. `/health` is unauthenticated liveness only. Production requires same-site HTTPS deployment, strong SECRET_KEY, explicit ALLOWED_ORIGINS, COOKIE_SECURE=true, database migration job, private database and externally enforced distributed rate/concurrency limits. See README for SMTP and local model protocol.
